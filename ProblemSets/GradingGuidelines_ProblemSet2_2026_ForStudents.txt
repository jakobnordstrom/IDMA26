PROBLEM 3: MERGERUNSSORT

Problem 3a (30 p)
10 p for arguing correctness of merge
20 pr for arguing correctness of mergrunssort (given that merge is correct)
Half of the points for a partially correct argument for either subproblem
A clear explanation that we have seen merge in class, and this algorithm is essentially the same that we saw in class, is sufficient for correctness of merge. Note, however, that it is not possible to just silently assume that the piece of given code is correct — there is nothing in the problem statement supporting such an optimistic assumption.
For mergerunssort, we don't need any formal induction proof, but we want to see a clear inductive argument that:
- The first subarray is sorted because the codes just generates the longest already sorted array.
- The second array will be sorted after the recursive call, since by induction smaller arrays are sorted correctly.
- Since merge is correct, all of the array will be sorted correctly.

Problem 3b (30 p)
Correct argument for termination: 10 p
Correct complexity analysis / running time: 20 p

Correct running time recursion T(n) = Kn + T(n-1) but not more: 10 p
Correct running time O(n^2) but no discussion of whether this worst case can actually happen (anywhere in the solution of Problem 3): -5 p
